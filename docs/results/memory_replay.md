# 记忆库逐条回放核对

命令：`memocore memory-replay --budget 20`（不调用 LLM）。原始数据见 [memory_replay.json](memory_replay.json)。

做法：为 LoCoMo 的每段对话建一个空的 `MemoryStore`，按会话顺序一条一条调用 `add` 写入全部 5,882 轮（和 Agent 实际写入的方式一样），再对 1,540 道题调用 `search`。同时用评测时的 `HybridRAGSystem`（默认配置：BM25 补充候选 + 重排 50 + 时间锚定 + 伪相关反馈）直接处理同一段对话，逐题比较两边选出的轮次。

| 指标 | 结果 |
|---|---|
| 记忆库给出的编号与 LoCoMo 原编号一致 | 5,882 / 5,882 轮 |
| 两边选出的轮次逐题一致 | **1,540 / 1,540** |
| 证据召回（20 轮预算） | 87.53%，与 [检索消融](retrieval_ablation.md) 默认配置的 87.53% 相同 |
| 多跳 / 时间 / 开放域 / 单跳 | 73.9% / 91.2% / 61.6% / 93.5% |
| 库文件大小 | 27.3 MB |

回放时向量和重排分数走的是评测缓存，所以回放里的耗时不代表真实延迟。真实延迟另外测：关闭所有缓存，用 conv-26（419 轮）逐条写入，再检索 30 题，RTX 5060 笔记本：

| 操作 | 中位数 | p95 |
|---|---:|---:|
| 写入一条消息（时间锚定 + bge-m3 编码 + SQLite 落盘） | 26 ms | 42 ms |
| 检索一次（向量 + BM25 + 伪相关反馈 + bge-reranker 重排约 70 对） | 295 ms | 330 ms |
| 写入后第一次检索（含重建索引） | 315 ms | — |
| 打开库后的第一次检索（含建索引） | 405 ms | — |
