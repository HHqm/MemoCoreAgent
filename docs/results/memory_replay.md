# 记忆库逐条回放核对

命令：`memocore memory-replay --budget 20`（不调用 LLM）。原始数据见 [memory_replay.json](memory_replay.json)。

做法（2026-11-03 用第 5 轮确定的默认配置重跑）：为 LoCoMo 的每段对话建一个空的 `MemoryStore`，按会话顺序一条一条调用 `add` 写入全部 5,882 轮，每写完一个会话就检索一次（共 272 次，和 Agent 边聊边查的用法一样），再对 1,540 道题调用 `search`。因为中途一直在检索，这些题用的索引是随写入一路增量扩展出来的，不是一次建好的，所以这项核对同时验证了增量索引。同时用评测时的 `HybridRAGSystem`（默认配置：BM25 补充候选 + 重排 50 + 时间锚定 + 伪相关反馈 + 时间感知查询 + 说话人先验）直接处理同一段对话，逐题比较两边选出的轮次。

| 指标 | 结果 |
|---|---|
| 记忆库给出的编号与 LoCoMo 原编号一致 | 5,882 / 5,882 轮 |
| 两边选出的轮次逐题一致 | **1,540 / 1,540** |
| 证据召回（20 轮预算） | 88.38%，与 [检索消融](retrieval_ablation.md) 默认配置的 88.38% 相同 |
| 多跳 / 时间 / 开放域 / 单跳 | 74.7% / 91.6% / 63.2% / 94.5% |
| 库文件大小 | 27.3 MB |

回放时向量和重排分数走的是评测缓存，所以回放里的耗时不代表真实延迟。真实延迟另外测：关闭所有缓存，用 conv-26（419 轮）逐条写入，再检索 30 题，RTX 5060 笔记本：

| 操作 | 中位数 | p95 |
|---|---:|---:|
| 写入一条消息（时间锚定 + bge-m3 编码 + SQLite 落盘） | 24 ms | 26 ms |
| 检索一次（向量 + BM25 + 伪相关反馈 + bge-reranker 重排约 78 对） | 295 ms | 334 ms |
| 写入后紧接着检索（索引只追加新轮次） | 303 ms（600 条）/ 317 ms（2 万条） | — |
| 打开库后的第一次检索（含建索引） | 336 ms | — |
