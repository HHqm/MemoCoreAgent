# API 使用与成本（2026-11-03）

先免费审计已有的调用记录和官方文档，再用小样本付费探测（共约 ¥1）验证。结论：**输出（几乎全是思考）是花费的大头，关闭思考能省 41%～72%。300 题配对检验（第 6 节）显示作答关闭思考没有看到准确率下降；裁判关闭思考则会明显放宽判分口径，不能直接替换。**

## 1. 审计：钱花在哪

已有的 300 题运行（deepseek-flash 作答，deepseek-v4-pro 严格裁判）：

| 运行 | 每题输入 token | 命中前缀缓存 | 每题输出 token | 输出 p95 |
|---|---:|---:|---:|---:|
| naive_rag | 1,236 | 12.4% | 138 | 381 |
| hybrid_rag v1 | 1,381 | 14.3% | 123 | 348 |
| hybrid_rag v3 | 1,723 | **2.5%** | 304 | 923 |
| full_context | 21,310 | 96.2% | 141 | 332 |
| 严格裁判（每次） | 约 360 | 约 0% | 307～369 | 1,040～1,673 |

- **输出几乎全是思考**：回答本身约 15 个 token，裁判的 JSON 约 40 个，其余都是思考，按输出价计费。
- **检索类系统几乎命中不了缓存**：v1～v3 把记忆放在最前面，而记忆每题都不同。
- **截断重试少算了一次**：被截断后加倍重试时，只记了第二次调用的 token。

到目前为止全部运行合计 ¥16～30（`memocore cost`；旧记录没有调用时间，给出低谷价到高峰价的区间）。一次 300 题的系统评测（作答 + 裁判）约 ¥1.3～3.3。

## 2. 官方文档里和本项目相关的规定

来源：[定价](https://api-docs.deepseek.com/quick_start/pricing)、[上下文缓存](https://api-docs.deepseek.com/guides/kv_cache)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)（2026-10 版本）。

| 规定 | 对本项目的影响 |
|---|---|
| 每百万 token：flash 命中缓存 ¥0.04、未命中 ¥2、输出 ¥8；v4-pro 为 ¥0.30 / ¥9 / ¥27（高峰价） | 输出是输入的 4 倍，命中缓存是未命中的 1/50 |
| 低谷时段半价：工作日北京时间 9:00～12:00、14:00～18:00 以外，周末全天 | 批量评测放到低谷跑 |
| 缓存只在完整匹配"前缀单元"时命中；多个请求出现共同前缀后，这段前缀才成为单元 | 固定文本要放在最前面，第三次请求起才能命中 |
| 默认开启思考（effort high）；思考模式下 temperature 不生效 | 以前设的 temperature=0 并没有作用 |
| `thinking: {"type": "disabled"}` 关闭思考，`reasoning_effort` 可设 low / high / max | 作答和裁判都可以选择思考程度 |

## 3. 改了什么

- **逐次计费**：每次调用记录命中缓存、未命中、思考 token 和调用时间（UTC），按调用时段的单价算出花费（元），运行汇总里显示每个阶段花了多少钱。
- **截断重试照实计**：两次调用的 token 和花费都算上。
- **`memocore cost`**：统计各次运行实际花了多少；从缓存取回的回答不重复计费。
- **开跑前预估**：`run` 和 `judge` 在调用前打印预计花费、当前是否高峰、几点起半价。
- **`--reasoning none|low|high|max`**：选择回答模型的思考程度，写进运行指纹，不同设置不会混在一个运行里；不设时与以前的请求完全相同，已有缓存照样命中。
- **提示词 v4**：与 v3 逐字相同，只是把固定的说明和示例放到记忆前面，便于缓存。

## 4. 小样本探测（约 ¥1）

同样 30 题（每段对话 3 题），检索结果与 300 题 v3 运行完全相同，只改提示词顺序或思考程度：

| 作答方式 | 每次输出 token | 其中思考 | 延迟 p50 / p95 | 每次花费（高峰） | 输入命中缓存 |
|---|---:|---:|---:|---:|---:|
| v3（现行） | 323 | — | 2.6 s / 5.3 s | ¥0.0061 | 0% |
| v4（固定文本在前） | 362 | 340 | 1.9 s / 6.1 s | ¥0.0058 | 16.5% |
| v3 + 关闭思考 | **17** | 0 | **1.1 s / 1.6 s** | **¥0.0036** | 0% |
| v3 + 低思考 | 240 | 218 | 2.2 s / 4.2 s | ¥0.0054 | 0% |

- **v4 的缓存确实生效**：从第二次调用起每次命中 256～512 个 token，但输出才是大头，总花费只少约 4%。
- **关闭思考最省**：输出少 95%，花费少 41%，延迟少 58%；答案有好有坏（列全了 5 个游戏，但也漏了"胶片相机"），30 题看不出整体好坏。
- **低思考**：花费只少 11%，不值得。

**同一 prompt 重答一次**（换一个空的本地缓存，跳过已有回答）：

| 模式 | 去掉引用后答案相同 |
|---|---:|
| 思考（默认） | 17/30（43% 变了） |
| 关闭思考 | 23/30（23% 变了） |

思考模式下 temperature 不生效，同一个问题重答，近一半答案的写法或内容会变。这解释了 prompt 调优的噪声底（每换一版都有 12～16 题对错翻转），也说明本地响应缓存是结果可复现的前提。

**裁判关闭思考**，重判 100 道盲审题（[judge_audit.md](judge_audit.md)）：

| 裁判 | 与 Claude 盲审一致 | 同一批题的准确率 | 每次输出 token | 每次花费（高峰） |
|---|---:|---:|---:|---:|
| 严格裁判，思考（现行） | 80/100 | 42% | 约 369 | ¥0.0132 |
| 严格裁判，关闭思考 | **89/100** | 57% | 42 | **¥0.0037** |

不思考的裁判便宜 72%，而且更接近盲审：它和思考裁判有 19 题分歧，其中 15 题与盲审一致，多是思考裁判把"多带一个无害细节"判成越界；另有 3 题比盲审宽、2 题比盲审严。盲审标签也来自模型，不是人工。

## 5. 结论与建议

- **已经采用（不影响结果）**：逐次计费、开跑前预估、截断重试照实计、思考程度选项。
- **省钱最直接的办法**：批量评测放在低谷时段跑（半价），开跑前看一眼预估。
- **作答推荐关闭思考，但不改 CLI 默认值**：300 题检验里没有看到准确率下降，作答花费约 -40%、延迟中位数 2.03 s → 1.43 s（第 6 节）。默认值不改，是因为已发布的运行都用服务商默认的思考模式，改了以后按文档命令复现会悄悄换成另一种设置，也用不上已有的响应缓存。新实验加 `--reasoning none`。
- **裁判保持思考**：关闭思考的裁判在 300 题上把准确率从 55.0% 判成 67.3%，口径变了，和历史结果不可比。它和盲审更接近（第 4、6 节），可以作为第二口径一起报告，但不替换。
- **v4 提示词**：节省有限（约 4%），保留为选项，不替换默认的 v3。

## 6. 300 题配对检验（2026-11-03 晚，低谷时段）

脚本在北京时间 18:00 自动开跑（`--wait-off-peak`），今晚实际花费约 ¥1.4（作答 ¥0.48，关闭思考的裁判重判 v3 ¥0.31，严格裁判判新答案约 ¥0.6，其中约 ¥0.5 是崩溃那次已付费、没记上账、按同批单价推算的部分，见下文）。

**作答关闭思考**：同样 300 题，用同一个严格裁判（思考）判分。

| 比较 | 题数 | v3（思考） | 关闭思考 | 差值 | 95% 置信区间 | p |
|---|---:|---:|---:|---:|---|---:|
| 全部 | 300 | 55.0% | 59.3% | +4.3 | [+0.0, +9.0] | 0.056 |
| 检索完全相同，只差思考开关 | 66 | 59.1% | 57.6% | -1.5 | [-9.1, +6.1] | 0.89 |
| 检索也变了（多了伪相关反馈） | 234 | 53.8% | 59.8% | +6.0 | [+0.9, +11.5] | 0.03 |

- **这不是只改一项的对照**：v3 那次运行没开伪相关反馈，而现在的默认值开着，排程脚本里我漏关了这一项，所以 234 题的检索也不同（证据召回 87.1% → 89.6%）。`compare` 现在会列出两次运行的设置差异，改了不止一项时直接提示不能归因。
- **能下的结论**：只差思考开关的 66 题上看不出差别（3 题只有关闭思考答对，4 题只有思考答对）；整体提升主要来自检索。所以"关闭思考不降准确率"有支持，但 66 题的置信区间很宽（±7.6 个点）。要干净地单独测思考开关，还需要关掉伪相关反馈重答 234 题、再判分，约 ¥1.4。
- **代价**：关闭思考后每次输出中位数 13 token（思考时 166），作答每题约 ¥0.0018（思考时约 ¥0.0029），延迟中位数 2.03 s → 1.43 s；带出处的回答 96.3% → 97.3%，引用精确率 78.7% → 79.5%，引用全部落在上下文内。

**裁判关闭思考**：同一批 v3 答案，两个裁判各判一遍。

| 指标 | 结果 |
|---|---|
| 两个裁判在需要 LLM 判的 201 题上一致 | 160 / 201 = 79.6%，κ = 0.60 |
| 分歧方向 | 39 题关闭思考判对、思考判错；只有 2 题反过来 |
| 300 题准确率 | 思考 55.0%，关闭思考 **67.3%** |
| 与盲审一致（这批答案里盲审过的 24 题） | 思考 18 / 24（κ 0.53，6 题偏严），关闭思考 21 / 24（κ 0.74，1 题偏松、2 题偏严） |

分歧几乎全是一个方向：思考裁判把"没写出标准答案里的理由""多带一个无害细节"（"headspace and mental health"）判成错。关闭思考的裁判更接近盲审，和第 4 节 100 题的探测一致；但它偶尔偏松，还出现过理由说"匹配"、结论却判错的自相矛盾。所以报告口径保持思考裁判（只偏严、是保守下限），关闭思考的裁判可以作为第二口径。

**过程中发现并修复的两个问题**：

- **空响应让整次运行崩溃**：DeepSeek 有一次返回了成功状态但没有 `choices`，OpenAI 客户端不会重试这种响应，程序在第 10 题处退出。现在遇到空响应会等 2 s、4 s 再问，三次都空才报错。
- **崩溃时漏记花费**：判分是 8 个线程并发的，一个线程出错时，其他线程已经完成的调用照样付了费、进了响应缓存，却没写进结果文件；补跑时它们作为缓存命中，记为 0 元。这次有 122 次调用是这样，按同批调用的单价推算约 ¥0.5。现在每个完成的调用都会先写入，所有线程结束后再抛出第一个错误。
