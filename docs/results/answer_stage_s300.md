# 作答环节：三版 prompt 的配对对比

## 出发点：错误归因

v1 下 hybrid_rag 答错 135 题，其中 92 题证据齐全。按裁判理由粗分：多答（多带细节或沾边的列表项）50 题，漏答或说得太笼统 41 题（其中 15 题两者都有），有证据仍拒答 7 题，其他 9 题。full_context 的分布几乎一样，说明问题在作答 prompt，不在检索。

## 三个版本

| 版本 | 改了什么 | 严格裁判 | 对 v1 的差值（95% CI，p） | F1 | 每题 prompt / 输出 token | 截断 |
|---|---|---:|---|---:|---:|---:|
| v1 | 短语作答，"只答被问到的" | 55.0% | — | 61.7% | 1,381 / 123 | 0 |
| v2 | 按错误归因加规则：保留名称、数字和限定词，不加沾边条目；用虚构人物的 few-shot 示范答案形式 | 56.3% | +1.3（[-2.0, +4.7]，p = 0.53） | 62.8% | 1,536 / 192 | 3 |
| v3 | v2 + 引用约束：上下文每行带轮次编号，答案必须引用出处，无法引用的内容不许写 | 55.0% | +0.0（[-3.7, +3.3]，p = 1.0） | 62.2% | 1,723 / 304 | 1 |

v3 的出处引用（对照 LoCoMo 标注的证据轮次；标注本身不全，所以精确率是下限）：

| 带引用的回答 | 引用精确率 | 标注证据被引用 | 引用落在上下文内 |
|---:|---:|---:|---:|
| 96.3% | 78.7% | 77.6% | 100.0% |

## 结论

1. **prompt 调优已经碰到噪声底**：三版之间每次都有 12～16 道题对错翻转，差值都在 ±1.3 个点内，配对检验都不显著。30 题抽查里看起来改好的 5～6 题，在 300 题上被另一些题的回退抵消了。因此停止在这个方向上花额度。
2. **引用约束不损失准确率，换来可追溯**：v3 与 v1 准确率相同，96% 的回答带出处，引用全部真实存在于上下文中（没有编造编号）。代价是 prompt token +25%、输出 token 约 2.5 倍。默认 prompt 改为 v3；只做 A/B、想省钱时用 `--prompt v1`。
3. **v2 的 3 条截断**发生在加入作答截断重试之前，按错误计分；之后作答与裁判一样，被截断时用双倍上限重试一次。
4. **和 full_context 的差距从哪来**：full_context 答对而 hybrid_rag 答错的 31 题里，只有 12 题是 hybrid 没召回全证据（7 题是多跳题）；反过来 hybrid 答对、full 答错的有 15 题。能靠工程追回的主要是这 12 题，于是转向检索：见 [retrieval_ablation.md](retrieval_ablation.md) 中的伪相关反馈（多跳题证据召回 +4.1 个点）。

## 省额度的做法

- 先在已有结果上免费做错误归因，再改 prompt。
- 用 `--qa-ids` 只重答 30 道定向抽查题（21 道证据齐全却答错的 + 9 道原本答对的），每版约 4.6 万 prompt token，只用来检查行为，不用来下结论。抽查的回答进了内容寻址缓存，正式跑 300 题时直接复用。
- 记忆在前、问题在后的 prompt 布局让 v2 的 A/B 运行有 74% 的 prompt token 命中了 v1 留下的前缀缓存。
- 本轮总花费：作答约 107 万 prompt token（42 万命中缓存）、16 万输出 token；裁判约 14 万 prompt token、13 万输出 token。规则预判省掉了 v3 运行 33% 的裁判调用。
